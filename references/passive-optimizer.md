# Passive Optimizer

The CLI measures legal trees; it does not generate ideas.

## Broad reviews: concept first

1. Refresh the build; its trusted scenario is the sole exact baseline.
2. Map load-bearing layers, dependencies, shared investment, and stranded
   investment with `build-layers.md`.
3. Search current builds, mechanics, and adjacent or old archetypes. Revalidate
   old versions instead of rejecting them by age.
4. Present 4-6 concept cards that replace, strengthen, or connect a named
   layer. Include dependencies, sacrifice, and cheapest falsification test.
5. Let the user select or combine 2-3 concepts.
6. Search bounded permutations inside each concept. Global brute force is
   diagnostic only.
7. Exact-check a complete concept and a nearby control with `poe2-forge.js
   directed`. Surface only measured useful results.

Use `poe2-forge.js passive` for legality/search/reporting. Preserve
connectivity, budgets, starts, ascendancy, sockets, choices, and unrelated
state. Cheap scores triage; PoB decides. Never apply candidates automatically.

Raw search artifacts are machine-only and can be many megabytes. Never open
them. Consume the default packet or query exactly one candidate with `passive
report --inspect-candidate ID`.
