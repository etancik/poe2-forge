# Idea Discovery

Use for broad non-passive reviews or new directions. For passive-tree work load
`passive-optimizer.md` instead.

First map the current build with `build-layers.md`. Search for replacements of
whole layers or new connections between layers, not isolated upgrades.

Search several independent angles: current builds sharing the primary skill;
mechanic discussions and patch notes; adjacent ascendancies or skills using the
same scaling; and older examples worth translating. Record URL, date or patch
when known, and the transferable mechanic rather than copying a whole build.

Classify evidence as `current`, `needs-revalidation`, `translated-current`,
`invalid-current`, or `measured`. An old patch or unknown version is a
verification task, never an automatic rejection. Discard only duplicates,
proven impossible dependencies, or ideas unrelated to the goal.

Present 6-8 concept cards with the layer change, dependencies, stranded
investment, replacement package, source/status, playstyle impact, acquisition
footprint, respec impact, main uncertainty, and smallest useful test. At this
stage do not run detailed market pricing; mark whether requirements are owned,
exchange-priced, rare/manual, or still underspecified. Do not discard expensive
or dream-tier cards.

Let the user select or combine 2-4 cards. Measure those, discard illegal or
irrelevant results, then send every surfaced acquisition package to
$estimate-poe2-build-costs once as alternative candidates in one snapshot.
